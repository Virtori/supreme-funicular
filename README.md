# Универсальный отчёт ТОиР · 2.2

Автономный `index.html` для актуального Chrome/Edge. Два источника: универсальная выгрузка ЗН и заявки/позиции ТМЦ (XLSX, CSV, TSV). Данные обрабатываются локально; рабочие выгрузки в репозитории отсутствуют.

## Методика

Обзор использует адаптацию принципов SMRP: невыполненные работы, очередь до начала, спланированные работы (включая готовые), подтверждённо готовые, работы в исполнении, физически выполненные, отменённые и не классифицированные ЗН. Это не заявление о сертифицированном соответствии. Значения статусов конкретной EAM нужно подтвердить.

Откройте «Методика SMRP» и задайте единицы часов, карту статусов, охват и доступный ресурс по специальностям. По умолчанию единицы не подтверждены, расчёт человеко-часов и недель заблокирован. В режиме длительности суммируются длительность × численность по уникальной работе и специальности. В режиме человеко-часов итог ЗН используется один раз и сверяется с полной разбивкой операций. Противоречия блокируют расчёт, максимальное значение не выбирается автоматически.

Для Ready необходимы подтверждения планирования, оценки труда, материалов, инструмента, доступа и безопасности. Поля названы в методике отчёта. Отсутствие связанной заявки ТМЦ не доказывает готовность. Частично полученные материалы остаются ограничением. Возраст от создания не подменяет просрочку согласованного срока.

Planned и Ready в неделях считаются по ресурсу той же специальности и при подтверждённой полноте данных. Объём Planned уже включает Ready. Это горизонт нагрузки, не прогноз закрытия с учётом новых работ.

## Работа с историей

Загрузите оба файла, выберите листы и дату, затем зафиксируйте срез. История новой методики сравнивает одинаковые версии единиц и карты статусов. Локальная история прежних разрезов и тренды ТМЦ сохранены отдельно. Историю можно переносить через JSON или сохранённый HTML. Для сохранения выгрузок, настроек, истории и недельных планов нажмите «Сохранить HTML с данными».

Недельный план фиксируется по «Проект недели №NN-YY». Локальный KPI по ЗН использует неизменный список, подтверждение исходного плана до начала выполнения и даты завершения в пределах недели. Без необходимого охвата и подтверждения результат не выдаётся за достоверный процент.

Источники методики и полные правила находятся в отчёте. MTBF/MTTR/OEE без данных об отказах, простоях и наработке не рассчитываются.

## Простой обзор и диаграммы

Основной экран содержит пять показателей и десять диаграмм исходных данных: статусы ЗН, структура работ, нагрузка по планировщикам, департаменты, приоритеты, возраст, виды ремонта, состояние поставок, просрочка по снабжению и поставщикам. Диаграммы учитывают выбранные фильтры; ЗН считаются уникально, ТМЦ — по строкам позиций. Каждый график можно скачать в SVG; круговые диаграммы экспортируются с легендой и процентами.

Палитра адаптирована на основе нейтральных цветов ТЕХНОНИКОЛЬ: графит, белый, серый и серо-синий с приглушённым бордовым акцентом. Яркий корпоративный красный не применяется. Основные формулы изложены в четырёх коротких правилах; подробная методика и настройки доступны в раскрывающихся разделах.

## KPI / NASA

Добавлено отдельное поле загрузки XLSX KPI с листом «Данные недели». Недельные данные, параметры ресурсов, определения статусов и архив KPI хранятся отдельно от текущего бэклога. Для файла бэклога дополнительно читаются исходная сводка и архив истории.

Во вкладке «KPI / NASA» показаны сверка строк с уникальными ЗН, исходные и пересчитанные показатели плана и ПО, доступный ресурс по отделам и графики источников. Служебный флаг бэклога применяется только для сверки одного и того же охвата. Исторические показатели Excel не пересчитываются задним числом без исходных выгрузок и не называются новыми метриками NASA.

Методическая опора: NASA NPR 8831.2F, приложение G и главы 3/7. Аварийность определяется как фактические аварийные часы / все фактические часы; местный показатель «вразрез + аварийные / план» остаётся отдельным. Часы требуют подтверждения единиц, периода и полноты. Выполнение графика по часам, завершение ЗН по текущим статусам и завершение в соответствии с исходным графиком — разные показатели. Ресурс из файла бэклога не заменяет недельный ресурс KPI. Расчётный остаток ресурса не доказывает наличие незарегистрированных трудозатрат.

Применение NASA здесь является адаптацией руководства по эксплуатации объектов, а не сертификатом соответствия или обязательным нормативом для предприятия. Источники и ограничения доступны прямо в отчёте.
